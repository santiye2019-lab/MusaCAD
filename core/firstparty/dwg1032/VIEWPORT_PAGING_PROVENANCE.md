# Independent viewport visibility paging (2026-11-02)

- **Scope:** `core/firstparty/dwg1032/` in existing MusaCAD, not `MusaCAD2/`. New C11 `musa_dwg1032_viewport_local_visibility_page` computes a selected page of a *caller-verified, already decoded* entity/layer/viewport state. It delegates to the existing strict local visibility resolver and does not infer block instance ownership, parse compressed DWG pages, or grant final rendering permission.
- **Source origin:** Independently written bounds checks, pointer-range exclusion, and slice delegation using only standard C11 and existing first-party MIT modules. No GPL, AGPL, LGPL, LibreDWG, legacy native-core or unknown-origin implementation was copied, adapted, imported or linked. The standalone target retains its existing isolation.
- **Data integrity:** Output cannot alias any byte of the *full* entity-layer or entity-visible arrays, even if the alias is outside the requested page. The underlying resolver also rejects output aliasing with layer/viewport metadata and validates all page handles/flags before publishing. Invalid ranges, malformed metadata, unknown handles and output overlaps fail without publishing any page bytes.
- **Synthetic coverage:** 20,000 entities, 128 layers, 16 viewport overrides; compare page sizes 1, 7, 257, 1,024 and 20,000 against the whole-array reference. Tests also cover viewport changes, late invalid handles/flags, malformed layer/override tables, source/metadata aliasing, zero/overflowing page sizes and override-free pages. No real-file performance speedup is asserted.
- **Remaining gates:** Actual AC1032 compressed-page recovery, genuine TEXT/MTEXT and INSERT record decoding, authenticated viewport state, 3D compatibility and Android full-scene integration are not established by this change. Android's historical GPL-marked `musacad_core` linkage is a separate unresolved release blocker. Do not enable production DWG import or report full CAD parity from these synthetic tests.
